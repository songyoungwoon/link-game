# LINK Game · ASTERFALL

같은 서버에 접속한 최대 8명이 같은 몬스터를 상대하는 독자적인 협동 RPG 알파입니다. 프로젝트 폴더는 `link-game`이며, 기존 작품의 캐릭터·미술·맵을 사용하지 않습니다. 게임 월드 주소는 `/link-game`입니다. LINK Browser의 PC 화면과 PC OpenXR VR에서 같은 세계에 접속합니다.

서버가 몬스터 체력·AI·공격 거리·무기 쿨다운·피해·보상·퀘스트·리스폰을 판정합니다. 캐릭터 레벨·경험치·골드·장비·퀘스트 진행은 SQLite에 저장됩니다. 이는 소규모 신뢰 네트워크용 플레이 가능한 알파이며 대규모 MMO 운영 서비스는 아닙니다.

서로 다른 서버를 여행하는 NPC 시연을 추가했습니다. `LINK_GAME_NPC_START.cmd`로 두 서버를 시작하고 `LINK_GAME_NPC_PLAY.cmd`로 접속하세요. Liora는 브라우저가 닫혀 있어도 포탈을 통해 두 주소 사이를 이동하며 ID와 이동 횟수를 유지합니다. [NPC 이동·서버 운영 가이드](docs/npc-travel.md)를 참고하세요.

## 시작하기

Python 3.10 이상이 필요하며 별도 Python 패키지 설치는 필요하지 않습니다. 형제 `../link` 폴더에는 **shared-state-v1와 input-v1를 지원하는 최신 LINK Browser**가 빌드되어 있어야 합니다.

1. `LINK_GAME_SERVER_START.cmd`를 실행합니다. 기본 TCP 포트는 8002입니다.
2. 같은 PC에서 `LINK_GAME_PLAY.cmd`를 실행합니다.
3. VR로 열려면 Quest Link와 PC OpenXR를 준비한 뒤 `LINK_GAME_PLAY.cmd --vr`를 실행합니다.
4. 서버를 끝낼 때는 서버 창에서 `Ctrl+C`를 눌러 진행을 저장합니다. 실행기는 다른 앱이나 이미 포트를 사용하는 프로세스를 종료하지 않습니다.

명령줄 실행도 가능합니다. 기본 월드와 DB 경로는 작업 폴더에 관계없이 이 서버 파일 위치를 기준으로 정합니다.

```powershell
.\LINK_GAME_SERVER_START.cmd
.\LINK_GAME_PLAY.cmd
.\LINK_GAME_PLAY.cmd --vr
python .\server\asterfall.py --host 0.0.0.0 --port 8002
```

포트가 이미 사용 중이면 해당 서버 창의 상태를 확인하거나 다른 포트를 선택하세요. 다른 포트를 사용하면 브라우저에서도 그 포트의 LINK 주소를 직접 입력해야 합니다.

```powershell
.\LINK_GAME_SERVER_START.cmd --port 8003
# LINK Browser 주소창: link://127.0.0.1:8003/link-game
```

## 여러 사람이 같은 세계에 접속

다른 PC에서는 서버 창의 실제 Ethernet/Wi-Fi IPv4 주소를 사용합니다. 예를 들어 서버가 `link://192.168.0.10:8002/link-game`를 출력하면 모든 플레이어가 그 주소를 LINK Browser 주소창에 입력합니다. `127.0.0.1`은 현재 PC만 가리키고, `0.0.0.0`은 수신 설정값입니다. 가상 어댑터 주소가 함께 출력될 수 있으므로 실제 연결된 인터페이스를 선택하세요. `ipconfig`로 확인할 수 있습니다.

같은 PC에서 두 캐릭터를 시험하려면 서로 다른 프로필을 사용하세요.

```powershell
.\LINK_GAME_PLAY.cmd --profile alice --player-name Alice
.\LINK_GAME_PLAY.cmd --profile bob --player-name Bob
```

프로필별 접속 토큰은 기본적으로 `%LOCALAPPDATA%\LINK\profiles\<profile>.sessions`에 저장됩니다. 같은 프로필·서버·월드에 다시 접속하면 같은 캐릭터를 이어서 사용합니다. 하나의 캐릭터로 동시에 두 번 접속하면 서버가 거부합니다. 프로필 파일을 잃으면 기존 캐릭터를 자동 복구할 수 없으므로 필요한 경우 안전하게 백업하세요.

TCP 8002 연결이 현재 네트워크 정책에서 허용되어야 합니다. 이 실행기는 방화벽이나 공유기 설정을 변경하지 않습니다. 평문 TCP와 bearer 토큰을 사용하는 신뢰 LAN용 알파입니다. 외부 인터넷 공개용 TLS·계정 인증·복구 시스템은 제공하지 않습니다. 토큰 파일을 다른 사람에게 공유하지 마세요.

## 플레이 흐름

캠프에서 출발해 슬라임·늑대·골렘·워든을 상대합니다. 월드 안의 안내판과 무기·회복·퀘스트 스테이션을 클릭해 상호작용합니다. PC는 걷기/시선 이동과 클릭을, VR은 현재 LINK Browser의 컨트롤러 이동·회전·트리거 상호작용을 사용합니다.

스테이터스 창은 처음에는 닫혀 있습니다. **PC에서는 3D 뷰포트에 포커스를 둔 뒤 Tab**, **Quest 컨트롤러에서는 왼손 Y**를 한 번 눌러 열거나 닫습니다. 키를 누르고 있어도 한 번만 전환합니다. 이름·레벨·체력·경험치·골드·무기·처치 수·퀘스트 진행과 아이템 수량을 확인할 수 있으며, 아래쪽의 짧은 체력·퀘스트 표시는 계속 보입니다. 주소창을 입력하거나 Meta 시스템 화면에 포커스가 있을 때는 게임 메뉴 입력으로 전달하지 않습니다. 이 창은 개인 화면만 바꾸며 다른 플레이어와 몬스터의 진행을 멈추지 않습니다.

- 캠프의 시작 무기/철검 제단에서 무료로 장착합니다. 별검은 첫 퀘스트 완료 후 골드 100으로 처음 구매하고, 이후 무료로 다시 장착할 수 있습니다.
- 공격은 적의 3.5m 안에서 가능합니다. 회복·장비·퀘스트는 해당 스테이션의 4.5m 안에서 사용합니다.
- 같은 적에게 최근 20초 안에 피해를 주었고 처치 시 12m 안에 살아 있는 협동 참가자는 각자 한 번 보상을 받습니다. 단순히 근처에 서 있기만 하면 보상을 받지 않습니다.
- 적 5마리 처치 후 퀘스트 돌에서 골드 100을 받습니다. 워든을 처치한 뒤 다시 보고하면 마지막 퀘스트 보상을 받습니다.
- 체력이 0이 되면 3초 뒤 캠프에서 부활합니다. 캠프의 회복 사당으로 체력을 회복할 수 있습니다. 사망해도 장비·골드·퀘스트 진행을 잃지 않습니다.

| 무기 | 기본 피해 | 공격 간격 |
| --- | ---: | ---: |
| 시작 무기 | 12 | 0.65초 |
| 철검 | 25 | 0.55초 |
| 별검 | 40 | 0.50초 |

레벨은 누적 경험치 100마다 오르며 최대 체력이 증가합니다. 적은 일정 시간이 지나면 다시 나타납니다. 서버 재시작 시 몬스터 세계 상태는 새로 시작하며, 재접속 캐릭터는 저장된 진행을 가지고 캠프로 돌아옵니다. 플레이어 위치 자체는 영구 저장하지 않습니다.

## 탐험과 채집

맵은 동서 **240m**, 남북 **250m**이며 기존 초원보다 면적이 약 13배 넓습니다. 캠프에서 분기 길을 따라 네 지역으로 탐험합니다.

| 지역 | 방향·위치 | 볼거리 |
| --- | --- | --- |
| 속삭이는 숲 | 서쪽, 약 X -70 / Z -28 | 거목과 숲의 길, 흩어진 채집 식물 |
| 열린 관측소 | 동쪽, 약 X 64 / Z -33 | 들어가 볼 수 있는 지붕·기둥 건축물과 유적 |
| 새벽의 성소 | 북쪽, 약 X 0 / Z -125 | 원환 성소와 파수꾼 |
| 고요한 정원 | 남쪽, 약 X -28 / Z 80 | 수면 정원과 다리 |

몬스터 **12마리**가 서식지 주변을 순찰하고, 플레이어를 발견하면 추적하며 멀어지면 귀환합니다. 캠프 중심 반경 13m는 안전 구역입니다. 채집 지점은 **16곳**입니다. 꽃·잎·열매에 2.8m 안으로 다가가 PC에서 클릭하거나 VR 광선으로 가리키고 트리거를 누르세요. 먼저 채집한 플레이어가 1개를 획득하고 식물은 60초 뒤 다시 자랍니다. 다른 플레이어에게도 채집된 상태가 보입니다.

**Tab / 왼손 Y**로 여는 스테이터스 창에 인벤토리도 표시합니다. 달빛잎·햇살꽃·산딸기는 채집으로, 슬라임 젤·늑대 송곳니·고대 조각은 전투의 협동 보상으로 얻습니다. 아이템은 개인별로 저장하고 현재 최대 16종·종류별 99개로 제한합니다. 채집물의 해당 스택이 가득 차면 식물을 소모하지 않습니다. 몬스터 재료 스택이 가득 차더라도 경험치·골드 보상은 받습니다. 이번 버전의 재료는 획득·보관·조회 기능을 제공하며 제작·거래·재료 사용은 후속 범위입니다.

## 저장과 백업

기본 저장 파일은 공개 월드 폴더 밖의 `data/characters.sqlite3`입니다. 서버에는 원본 접속 토큰 대신 SHA-256 해시만 저장합니다. 보상·장비·퀘스트·인벤토리 변화는 즉시 커밋하고, 접속 종료·주기적 저장·정상 서버 종료에서도 저장합니다.

가장 간단한 백업은 `Ctrl+C`로 서버를 정상 종료한 뒤 `data/characters.sqlite3`를 안전한 다른 폴더에 복사하는 것입니다. 캐릭터를 계속 사용하려면 각 플레이어의 프로필 토큰 파일도 별도로 보관해야 합니다. 실행 중 단일 DB 파일만 복사하지 마세요. 실행 중 백업이 필요하면 SQLite 백업 API로 일관된 사본을 만들 수 있습니다.

```powershell
# link-game 폴더에서 실행. 백업도 공개 worlds 밖의 data에 둡니다.
python -c "import sqlite3; a=sqlite3.connect(r'data\characters.sqlite3'); b=sqlite3.connect(r'data\characters-backup.sqlite3'); a.backup(b); b.close(); a.close()"
```

다른 저장 파일이나 월드 폴더를 지정할 수 있습니다. DB 경로를 공개 월드 안으로 지정하면 서버가 시작을 거부합니다.

```powershell
python .\server\asterfall.py --database "D:\AsterfallData\characters.sqlite3" --worlds "D:\AsterfallWorlds"
```

기존 캐릭터 DB를 처음 갱신할 때는 SQLite 백업 API로 WAL의 미반영 내용까지 포함한 `<DB 파일명>.pre-inventory.bak` 사본을 만든 후 인벤토리 열을 추가합니다. 이미 있는 백업은 덮어쓰지 않습니다. 레벨·장비·골드·퀘스트와 캐릭터 ID는 그대로 이어지며 초기 인벤토리는 비어 있습니다.

## 프로토콜과 검증

같은 포트가 기존 LINK 0.1 문서 전송과 별도의 persistent shared-state-v1 연결을 처리합니다. 구체적인 프레임·스냅샷·월드 규약은 [공유 상태 규격](docs/protocol.md)에 있습니다. 매번 8개 플레이어 슬롯·12개 몬스터·16개 채집 지점과 본인만의 인벤토리를 응답하며 토큰을 스냅샷이나 로그에 포함하지 않습니다. 정해진 필드 외에 클라이언트가 체력·피해·골드를 보내면 거부합니다.

```powershell
python -m unittest discover -s tests -v
```

테스트는 실제 TCP 소켓과 두 클라이언트를 사용하며 공유 체력, 처치당 한 번의 협동 보상, 공격 쿨다운·거리, 부정 위치·NaN·중복 JSON·잘못된 순서·과도한 요청·크기 제한, 최대 8명·중복 토큰 거부, 사망/몬스터 리스폰, 재접속과 서버 재시작 후 SQLite 진행 복원을 확인합니다. 채집 거리·동시 획득·재생성·스택 한도·개인별 아이템 분리·전리품·인벤토리 영구 저장·구버전 DB 백업과 마이그레이션도 검사합니다. 긴 쿨다운과 리스폰을 기다리는 대신 테스트 전용 시계를 사용합니다. 전투 배치만 서버 내부 테스트 fixture로 준비하고 실제 클라이언트에는 순간이동/관리자 API를 제공하지 않습니다.

현재 범위는 작은 단일 PvE 세계입니다. PvP·거래·채팅·길드·다중 서버 샤딩·모바일 독립 실행·악의적 인터넷 환경의 부정행위 방어는 구현하지 않습니다.

## Moon Garden · 모델·애니메이션 데모

원본 애니메이션풍 탐험가와 아치 유적·물·꽃·조경을 갖춘 작은 정원을 새 주소로 제공합니다. `models-v1`을 지원하는 최신 LINK Browser를 빌드한 뒤 서버를 시작하고 `LINK_GAME_GARDEN.cmd`를 실행하세요. 이미 실행 중인 구버전 서버는 정상 종료 후 다시 시작해야 GLB 전송이 반영됩니다.

```powershell
.\LINK_GAME_SERVER_START.cmd
.\LINK_GAME_GARDEN.cmd
.\LINK_GAME_GARDEN.cmd --vr
# LINK 주소: link://127.0.0.1:8002/moon-garden
```

WASD로 정원을 걷고 마우스를 드래그해 둘러봅니다. 탐험가는 Idle·Walk 클립으로 순찰하고 클릭/VR 트리거에 Attack 클립을 재생합니다. 별도 시각 데모이므로 기존 `/link-game`의 캐릭터 진행·인벤토리와 공유하지 않으며, 이 NPC의 움직임은 접속자별로 실행됩니다. 기존 RPG 저장 파일은 사용하지 않습니다.

서버 없이 로컬에서 열려면 `..\link\build\native\Release\LINK.exe --worlds .\worlds --open link://local/moon-garden`을 실행합니다. 세계 원본과 생성 방법은 [모델 자산 문서](docs/moon-garden-assets.md), 브라우저 확장은 [models-v1](../link/docs/models-v1.md)에 있습니다. 이번 렌더링은 직접광·셀 명암·텍스처와 정원에 제작된 접지 음영을 사용합니다. 실시간 그림자·전역 조명이나 상용 엔진과 동등한 렌더러를 구현한 단계는 아닙니다.

## Stone Sanctum · 사실적 재질과 빛

조각 기둥·아케이드·부서진 천장·제단을 갖춘 원본 석조 성소입니다. Poly Haven의 CC0 촬영 기반 석재 재질과 Quarry 01 HDRI를 사용하며 노멀·거칠기·AO, 햇빛 그림자, HDR 환경광과 점광원을 보여줍니다.

최신 LINK Browser를 빌드하고 `LINK_GAME_SERVER_START.cmd`로 서버를 시작한 뒤 **`LINK_GAME_SANCTUM.cmd`**를 실행하세요. 실행 중인 구버전 서버는 정상 종료 후 재시작해야 HDR 전송이 반영됩니다. 주소는 `link://127.0.0.1:8002/stone-sanctum`입니다. 다른 PC에서는 서버 IP를 사용합니다. `LINK_GAME_SANCTUM.cmd --vr` 또는 F8로 PC OpenXR VR에 진입합니다.

서버 없이 열려면 `..\link\build\native\Release\LINK.exe --worlds .\worlds --open link://local/stone-sanctum`을 실행합니다. WASD와 마우스 드래그로 탐험합니다. 이 공간은 렌더링 데모이며 이동은 평면 영역으로 제한됩니다. 조명·재질 규격은 [lighting-v1](../link/docs/lighting-v1.md), 원본·재현 방법과 CC0 출처는 [자산 문서](docs/stone-sanctum-assets.md)에 있습니다.
